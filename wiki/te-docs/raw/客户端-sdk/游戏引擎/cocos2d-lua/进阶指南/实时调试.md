### 一、打印SDK日志
```lua
-- 开启打印日志
-- logLevelNone：打印日志关闭 
-- logLevelError：打印错误日志 
-- logLevelInfo：打印详细日志 
-- logLevelDebug：打印调试日志 
TDAnalytics.setLogLevel(TDAnalytics.logLevel.logLevelDebug)
```

<quote-container>
打开日志后，可以在IDE中过滤 ThinkingData 相关的日志来观察 SDK 的数据上报。
</quote-container>

### 二、开启 Debug 模式
开启Debug模式需要如下两步操作:
1. 客户端开启Debug模式
以下是客户端开启Debug模式的示例代码:
```lua
--[[
设置运行模式为 Debug 模式
debugOff模式:数据会存入缓存，并依据一定的缓存策略上报,默认为NORMAL模式；建议在线上环境使用
debugOn模式:数据逐条上报。当出现问题时会以日志和异常的方式提示用户；不建议在线上环境使用
debugOnly模式:只对数据做校验，不会入库；不建议在线上环境使用
]]
TDAnalytics.init(APP_ID, SERVER_URL, TDAnalytics.debugModel.debugOn)
```

2. AE 后台添加Debug设备
为了避免 Debug 模式在生产环境上线，规定只有指定的设备才能开启 Debug 模式。只有在客户端开启了 Debug 模式，并且设备 ID 在 AE 后台的"埋点管理"页的"Debug 数据"板块中配置了的设备才能开启 Debug 模式。
<image token="Iw5MbfQNXogHnBxtddNczkcPn8W" width="2309" height="857" align="center"/>

设备 ID 可以通过以下三种方式获取：
- AE 平台中事件数据中的 #device_id 属性
- 客户端日志：SDK 初始化完成后会打印设备 DeviceId
- 通过实例接口调用：[获取设备ID](https://thinkingdata.feishu.cn/wiki/JT03w6EvOiyVqckztCwcH3Kynm7)
<quote-container>
Debug 模式可能会影响数据采集质量和 App 的稳定性，只用于集成阶段数据验证，不要在线上环境使用。
</quote-container>
