# 追问与甄别

## 追问补证据缺口

| 缺口 | 示例追问 |
| --- | --- |
| 评价笼统 | “你说‘麻烦’，能回忆一个具体时刻吗？” |
| 过程缺失 | “在那之后，你做了什么？” |
| 选择依据不清 | “当时是什么让你选择这个方式？” |
| 结果不清 | “后来这件事进行得怎么样？” |
| 两段说法不同 | “这两次的情境有什么不同？” |

承接受访者实际说过的内容，一次补一个缺口。不编造引语，不机械重复“为什么”，不提供带方向的原因选项。不强制每个主题追问固定次数；没有缺口就进入下一主题。

设计方案时给出候选追问及适用条件，它们是主持指引，不是已部署的可执行路由。只有真实对话才能判断使用哪一条。

停止条件：证据已足够；没有新增信息；无相关经历或无法回忆；拒答、疲劳或不适；时间边界。停止时记录缺口，不施压制造答案。用户要求每题追问五次时，说明负担与诱导风险，建议用证据覆盖而非轮数控制深度。

## 甄别判断研究资格

仅在需要区分资格时设计，先明确纳入/排除条件。根据亲历、角色、近期行为提问，不把全部目标标准直接暴露为“你是否符合”。自行招募也可能需要核对资格，不按招募渠道一刀切。

资格门槛依据用户明确条件或研究目标必需的经历，不自行增加职业、行业或竞品从业等排除条件。额外控制条件只能作为待负责人确认的建议，确认前不写成生效的筛除规则。无法回忆具体细节或拒答不自动等于不符合资格；信息不足时标为待核实，可暂停或结束本次访谈，但不能据此认定其无资格或作弊。

为每道题写明选择方式、适用条件、通过/排除/待核实的解释，并按已确认的纳入/排除逻辑汇总资格：多个必要条件须全部核实满足才可通过；任一必要条件明确不满足或命中已确认的排除条件，则不符合；其余仍有未知条件时保持待核实。后续问题通过不能自动覆盖前题的未知，只能补足其实际提供的证据。例如能描述操作仅支持实际使用，不能单独证明使用发生在最近一个月；日期仍未知时不能确认资格。仅在研究目的要求时增加额外条件分组，不自行扩展门槛。不能声称这些文字已经在平台中生效，实际配置须另行核对。

未知、其他、不愿回答与不符合资格分开处理。资格与质量分开判断：一次异常或前后差异不足以认定作弊。必要时中性核实，不凭语言流畅、表达风格或“像 AI”自动排除。

默认不用虚构品牌等陷阱。用户确需采用时，先说明验证目标、误伤可能、复核方式和参与者告知要求；未明确设计前不自动添加。不把此技能的建议称为法律或伦理审批。

避免索取密码、验证码、身份证件、完整账户等不必要资料。研究需要的敏感问题说明用途、最小化收集并允许拒答；具体同意和隐私安排由研究负责人确认。
