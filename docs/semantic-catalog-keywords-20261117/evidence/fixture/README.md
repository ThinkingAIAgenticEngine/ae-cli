# 语义目录关键词隔离夹具

本目录固定一组虚构“星岛餐厅”合成与餐厅经营业务材料，用于比较全量精简目录的候选召回与上下文成本。60 条语义、16 个自然业务问题，正文为本次真值；没有真实运营数据，也没有运行数值分析或召回评测。

## 文件与使用边界

- `rows.json`：60 条完整正文、旧标题/摘要/关键词、改写标题/摘要/关键词、来源及正文已有的显式依赖。包含不同实验条件，不能给盲测 Agent 整体读取。
- `queries.json`：仅含 `id` 和 `question`，可提供给每个独立测试 Agent。
- `bodies.json`：仅含 ID、正文与原有依赖。供固定候选后按 ID 读取正文；候选冻结前不应完整展示，否则变成全文召回实验。
- `gold.json`：必要直接候选、可接受额外候选、必要依赖及判定原因。仅供结果冻结后的评分者读取，禁止提供给召回测试 Agent。
- `catalog-A.json`：旧 title/summary，不含 keywords。
- `catalog-B.json`：旧 title/summary，加旧 keywords。
- `catalog-C.json`：改写 title/summary，不含 keywords。
- `catalog-D.json`：改写 title/summary，加改写 keywords。
- `freeze.json`：规模、来源与 gold 的 SHA-256；构造顺序为正文和原元数据、固定问题与 gold、改写元数据、四臂目录。
- `build_fixture.py`：离线可重建脚本，无网络或产品写入。脚本包含 gold，也不能交给召回测试 Agent。
- `validate_fixture.py` 与 `validation.json`：可复现的独立构造一致性检查与实际运行结果，不是召回效果。

四臂的条目顺序、ID、问题集一致。测试 Agent 只应接收一个 arm 的完整目录和 `queries.json`，不能接触其他臂、正文、gold、本 README 中的构造脚本。直接候选与依赖分开评分；测试阶段不要从目录缺少 dependency_ids 推断无需依赖。若测试阶段仅做候选选择，可另外记录依赖遗漏，不能因此把父条目的直接召回当失败。

## 构造来源

先读取指定 `scale-fixture/catalog.json`、`scale-fixture/expected.json` 和 `fixture-refinement/manifest.json`。既有 expected 仅说明历史三题目标，不作为本次 16 题 gold；本次没有复用历史召回选择或结果。

14 条核心语义来自 `docs/business-semantics/cli-consumption-20261116/fixture-lifecycle/state-final.json`，并核对 refinement 的原快照及收入正文：个人/共享日活、登录与通关、回访、格式、会员月报、活动参与与复盘、空结果、LTV、七日回收、收入净额、夏日资格及转化。旧元数据逐字保留；正文也逐字保留。选择的是 refinement 前已有版本，目的是保留真实原有质量差异，未人为缩短或劣化 baseline。适用个人/公共差异与失效规则均由正文决定。

另外 46 条来自原 300 条 scale 目录固定索引 `1 + 6*n (n=0..45)`，涵盖不同活动、组别与主题。原目录没有完整正文和 keywords；本次以原摘要全文加“星岛餐厅”范围作为正文真值，不补充活动门槛、数值、事件或新规则。旧 keywords 保持空数组，原标题和摘要保持不变。改写标题保留原文，摘要只调整事实顺序，关键词抽出同活动同组主题与跨组归并边界。

每个改写关键词须为同条正文的原文短语，或原快照已存在的别名。`sources.original_keywords` 明确保留原快照关键词，因而“厨房开门”“净流水”等旧别名有来源支持；没有凭直觉补充新别名。正文中出现的禁止混币、不能替代、资格失效等排除边界可以用关键词表达；不从常识发明负向条件。每条改写关键词 2–5 个，不使用泛化词云堆砌。

问题覆盖原有别名、相近个人/共享口径、条件与排除边界、跨条目依赖、多目标问题以及两道正文不支持的问题。gold 在脚本中先写入并计算摘要，再生成改写元数据；没有根据四臂运行结果修改 gold。

## 评分约定

`required_candidate_ids` 是直接回答问题必须读取的正文。`required_dependency_ids` 是进一步应用该规则所需的正文，包括父规则明确要求读取的依赖和正文要求的有效活跃规则。`acceptable_extra_candidate_ids` 可以补充上下文，不抵扣必要候选遗漏；除此之外的条目记录为额外候选。无命中问题的三个数组均为空。必要依赖允许第二阶段读取，不要求目录候选选择阶段凭摘要必然定位全部依赖；应分别报告直接候选覆盖、依赖覆盖及额外候选数。

## 局限

- 这是人工固定的合成材料，不代表线上语义分布、用户问题分布或真实效果。
- 46/60 条 baseline 本来就没有 keywords，A/B 在这些条目完全一致。因此 B/A 的差异仅反映现有 14 条关键词，而 D/C 同时涉及为原缺失条目补关键词，不能泛化为所有既有目录的效果。
- 活动干扰项大量使用相同模板，正文只拥有原摘要的信息量，没有真实活动配置。其真值边界比实际长正文简单。
- 核心语义包含个人/公共冲突、过期依赖与“没有数据”的历史合成设定，不能拿来证明当前环境是否具备数据或权限。
- 改写元数据来自人工阅读正文；自然问题与 gold 也由同一构造者固定，存在编写者偏差。没有优化过候选命中率，也没有承诺 D 一定优于其他臂。
- 上下文成本应按测试时实际发送的序列化内容计数，固定空格、字段格式和 tokenizer 后再比较；仅比较文件字节数不能直接当模型 token 数。

## 构造验收

运行 `python3 verification/catalog-keywords-20261117/fixture/build_fixture.py` 可重建。脚本校验 60 个唯一ID、16 道问题、gold 引用完整、改写关键词数量及逐条来源支持。独立校验还应检查四臂只含规定字段、旧元数据与来源一致、gold 摘要一致。此处不提供任何预测召回结论。

## 追加 E 臂：按额外上下文价值筛选关键词

`catalog-E.json` 维持 D 臂的 60 个 ID、条目顺序、标题和摘要逐字不变，唯一变量为 keywords。正文、问题、gold、A–D 文件均未修改。本轮不查看测试问题、gold 或既有盲测结果；仅按同条正文、来源、冻结标题和摘要审查关键词。

E 不沿用 D 构造时每条 2–5 个的数量要求。标题摘要已覆盖的主题、条件、否定边界，不再通过关键词重复。允许从原快照 keywords 恢复标题摘要未表达、来源明确的业务叫法，例如 DAU、留存、买量、净流水。候选词范围固定为 D 关键词与原快照关键词的去重并集，未额外扩充正文中的全部事件名或字段名，也未编造别名。

E 共保留 17 个关键词，分布于 12 条语义；48 条为 `[]`。其中 4 个来自 D 仍有额外价值的关键词，13 个恢复自原快照；删除 D 中 191 个重复关键词，另有 39 个原快照独有候选未恢复。原 D 共 195 个关键词。

`keyword-audit.json` 逐条列出 60 条语义的冻结标题摘要、D/E 关键词，以及候选词的 `keep`、`recover`、`remove` 决定、理由和来源证据。`recover` 只表示恢复原有叫法，不新增正文定义；例如参与转化、领奖转化仅是原快照术语，不表示本次补充了转化公式。

E 与 D 的比较隔离的是关键词编辑策略，包括删冗余和恢复既有术语；它不是 D 的纯删除子集实验。其效果仍需独立盲测，本审查不预测提升，也不据结果调整词表。E 文件 SHA-256 为 `d1afc5a9f1ca5a20278f5c0d4fd02eb55fde8017b2049f98badeaefffd6ec41b`。

注意：原 `build_fixture.py` 只重建 A–D，不生成或覆盖 E 与关键词审查记录。E 审查记录可供评审，但不能交给 E 盲测 Agent；盲测只使用 `catalog-E.json` 与既定问题，候选冻结后再按原机制读正文。
